# Bible Index

> 每次开始新对话前，先读这个文件；按任务匹配后只读对应的 1–2 个模块文件。

## 任何修改都不能违反（不变量）

1. 核心循环必须保留：瞄准 → 发射 → 看球弹 → 看球进袋洞 → 看球数变化 → 想再来一发。任何改动不得打断这条链。
2. 所有可调数值必须集中在 `SPEC.md` 的数值边界内，且用 `@export` 暴露在对应节点上，禁止散落在脚本里硬编码。
3. 球只能由 `BallTemplate` 复制产生，禁止在代码里凭空构造 RigidBody2D，保证物理参数一致。
4. 球数（库存）只能通过 GameManager 修改，任何节点不得直接自增自减库存球数。
5. 白盒阶段不引入正式美术资源、音效、粒子与后期特效。
6. 场景树里的固定物体（墙体、图钉阵、袋洞、HUD）必须是编辑器中可见的节点，禁止运行时动态拼装。

## 速查表：你要改什么，读哪个文件

| 你要改什么 | 读哪个文件 | 一句话提示 |
| --- | --- | --- |
| 改玩法规则、数值、胜负条件 | `SPEC.md` | 数值改动同步写回本文件 |
| 改某个系统的职责与接口 | `MODULES.md` | 跨 3 个以上模块先找我确认 |
| 调手感、判断"好不好玩" | `EXPERIENCE.md` | 改完回填测试记录 |
| 决定一件大事 | `99_decisions.md`（追加） | 格式：决策 #N / 日期 / 内容 / 理由 / 影响 |

## 不变量自检

改动提交前自问：这次改动有没有破坏上面 6 条中的任何一条？有就停下来说明原因，不要悄悄改不变量。
